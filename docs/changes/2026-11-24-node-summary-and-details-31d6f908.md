# 节点用简述讲业务，补充内容放详情

用户指出节点以“仍有需要的权限”概括授权条件，既未说明具体能力，也没有把清单和
解释放进详情。现有界面只有备注节点的悬停样式，读者不容易在浏览时发现补充说明。

[写图指导](../../.agents/skills/semantic-atlas/references/diagram-design.md#6-分清节点简述和详情)
明确标题概括具体业务意图，可见补充只保留读懂步骤与分支所需的信息；权限清单、
解释、举例和例外使用已有 `notes`。标题24字、可见补充40字是优先写作预算，允许
为必要含义适当超出，不做文件校验或界面截断。关键对象与决定路径的条件不能因压缩
而丢失。

同一 Viewer 在实际有非空备注的节点标题旁显示小信息标识。正文继续打开默认关闭
的详情，叠层角标继续进入子流程，两种用途明确区分。步骤备注与继承概念备注使用
原有优先级；无备注不显示标识，没有新增持久字段或独立操作按钮。

产品契约、架构及文件约定同步记录这一分工。既有渲染、CLI 和 Skill 相关30项检查、
类型检查、构建、lint、格式、文档链接及差异检查通过，没有为这次小改动新增测试。
独立代码审查发现默认图标在浅色结果卡片上偏淡，调整颜色后复审通过。

实际页面确认有备注显示信息标识、无备注不显示；正文打开业务说明，叠层角标仍独立
进入子流程并可返回，两种标识不重叠。云盘流程由原绘图作者按新指导调整，分清连接
状态、读取文件和创建文档的实际结果，主审对照源码复核；这是已有上下文中的定向
改进，不作为新上下文自主建图成功的证据。原本地预览地址已切换到当前源码构建。
源码合入、发布与全局安装分别按实际交付确认。
