# 2026-11-20 revise | 多入口与并行业务路径

- 变化：同一 `flow` 的 `startsAt` 接受单个 ID 或非空列表，解析后统一为入口列表；
  每个入口有效且不重复，所有步骤从至少一个声明入口可达。普通动作支持多个无条件
  后继，表示这些路径分别成立；判断仍有独立条件，结果仍结束当前路径。
- 依据：真实业务有多个用户／事件入口，同一事件也可能交给多个独立消费者。此前
  单入口与单后继限制会迫使编写者拆散这些联系，或误画成统一触发、择一路由。
  用户明确批准具体格式调整，并授权按适合目标的方案完成实现。
- 设计：复用原 `steps`、`transitions`、Dagre 布局及只读 Viewer，不增加执行引擎、
  图类型或数据库。全部入口显示开始样式，不补虚拟起点和汇合。多路入边不自动
  表示等待；具体等待对象仍由业务动作和说明表达。
- 公开结果：CLI `flows`／`context` 中的 `startsAt` 统一为 ID 列表，包版本以 4.0.0
  交付这一类型变化。原有单入口 YAML 继续可读。
- 影响：[格式](../map-format.md)、[架构](../architecture.md)、[产品契约](../product-contract.md)、
  [编写指南](../../.agents/skills/semantic-atlas/references/map-authoring.md)、
  [订单样例](../../examples/订单管理/README.md)及校验、查询、投影的相关业务检查。
- 验证：161 项检查和完整 `release:verify` 通过，独立源码审查通过。实际浏览器核对
  公开订单样例的多起点／并行，以及私有项目的总览、下钻、返回和多目标选择，页面
  错误为空。新版 Skill 新上下文试用自行生成含三个入口与两个独立消费者的总览，
  查询与渲染通过，样本运行缺口保持明确。私有业务资料在所属仓库维护，不进入包。
