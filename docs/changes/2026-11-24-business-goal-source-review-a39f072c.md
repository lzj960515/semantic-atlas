# 业务流程源文件按业务目标重整，并在交付前自审

此前取消强制项目全貌后，一次重整又把多项内部操作直接列为顶层业务，主图保留数段没有交代联系的小流程。用户重新检查发现这些问题及难以理解的措辞，说明前轮结构、代表性源码与局部阅读通过不足以证明整体交付达标。本记录补正[前轮画图指导](2026-11-23-teaching-first-authoring-37c8f780.md)对应的验收结论；旧记录保留当时证据。

[统一Skill](../../.agents/skills/semantic-atlas/SKILL.md)、[业务边界](../../.agents/skills/semantic-atlas/references/boundary-design.md)和[流程设计](../../.agents/skills/semantic-atlas/references/diagram-design.md)改为先说明读者要理解的业务目标，再判断每项操作为谁发生、对象怎样改变、结果怎样使用。独立接口、角色或返回值不自动成为顶层入口；多个独立业务仍可平级，不重新要求共同父图或固定规模。

AI的主要审查对象是业务流程源文件。作者边调查边保存，发现新证据立即重构，并在每个分块与完整交付前复盘业务目标、真实路径、连通片和自然语言。结构诊断帮助指出孤立节点及弱连通分量，是否应连接或分图仍按业务事实判断；不得为连通而编造顺序。业务代码核实规则与权限，网页核对布局与呈现，分别承担证据责任。当前未增加新文件格式、持久字段或强制单连通校验。

[产品契约](../product-contract.md)、[架构](../architecture.md)和[评估标准](../evaluation.md#讲解质量验收)已同步。只读独立审查用已失败产物核对，确认新指导能够指出顶层碎片、悬空片段和技术词拼接，同时保留正确的多入口与平级业务选择。

新上下文作者已按自然业务请求试作，规则从候选 Skill 读取。首块自审仍只移除零碎入口，独立验收退回后才补回必要运营过程；后续全范围复盘继续发现业务权限、分支作用范围、计费时间及可见技术措辞问题。由原作者返修，验收者未代画。全组可见文字、已报告问题、关键源码路径、格式、引用、代表性查询和渲染复核通过；较大流程仍需缩放，没有运行真实供应商或逐项验证全部辅助接口。

复核还发现删图后必要规则被藏在不可见的概念摘要里，以及不同复用结果被合成同一保存路径，作者已分别修正。文件编写指导据此明确 Web 实际显示的字段，要求重组时保留读者需要的规则；也说明现有 `validate` 的引用、分支与可达性检查不判断业务划分。当前没有新增正式检查工具。

本轮试作包含独立反馈，不能声称指导零干预成功或由一次结果推断长期可靠性；实际结果与边界记在评估页。Skill 资源的三份既有检查、共六项通过，修改文档链接和差异检查通过。源码合入、发布与安装分别按实际交付确认。
