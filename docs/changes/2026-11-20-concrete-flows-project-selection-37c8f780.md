# 2026-11-20 revise | 真实业务决定画法，产品负责项目查询

- 变化：统一 Skill 与产品说明取消隐含必备总览和统一起止框架。AI 根据实际动作、条件、
  交接与阅读需要决定图的边界和层次。独立流程通过导航分别浏览，软件不补执行关系，
  不自动将所有根流程拼成巨图。格式示例使用具体的预约取消路径。
- 理由：用户指出“收到业务操作→本次需要什么结果→返回处理结果”没有解释真实业务。
  把分类目录包装成判断分支不能建立业务含义，软件和 Skill 都不应替 AI 预设业务结构。
- 项目查询：复用已有 `ProjectStore` 的登记路径，通过 `ProjectDirectory` 派生名称与 ID。
  `project list` 返回名称、展示名、ID、路径；查询、校验、渲染与 Web 可用 `--project` 选择，
  与当前工作目录无关。未知名称返回相近候选，重名返回歧义候选，由调用者明确选择后重试。
  持久文件仍只有原有 `schemaVersion` 与 `paths`，不增加名字副本或全局业务索引。
- 影响：[产品契约](../product-contract.md)、[架构](../architecture.md)、[格式](../map-format.md)、
  [Skill](../../.agents/skills/semantic-atlas/SKILL.md)和双语 README。EX 的业务文件由其自身
  仓库修订；本产品变更不代表 EX 发布或部署。
- 验证：新增项目名/ID查询、误拼建议、重名消歧、不同项目同名业务隔离的 CLI 行为检查；
  隔离用户目录、外部工作目录下的构建版 CLI 与 Web 调用通过。159 项现有测试、类型检查、
  lint、格式、构建和构建版／打包安装检查通过，独立审查通过。新版 Skill 在一次新上下文
  试用中自行生成订单、履约与核算的 6 条具体流程，没有添加共同总入口；六图实际阅读
  通过，缺少调用方等证据明确保留。边界见[评估](../evaluation.md)。未发布此候选或修改
  全局安装。
