# 2026-11-20 revise | 项目业务全貌与跨仓库取证

- 变化：每个项目的业务资料都应有能向不熟悉项目的人讲清整体业务的一张或几张总览，
  再进入相关细图。零散接口的目录不能代替项目全貌；简单项目的一张完整业务图也能
  承担总览职责。总览的范围、画法和层次由 AI 根据真实业务决定，不固定图数或结构。
- 调查方法：先确认业务还缺少哪一环，再寻找前端页面、事件生产者、状态所有者或结果
  使用方所在的项目。仓库组织源码，业务边界与阅读范围另行判断。能读取的相关项目
  继续核实；不可访问的实现保留已知契约与具体缺口，不能编造内部流程。
- 格式边界：复用现有字段；跨项目 `search` 锚点记录来源项目与具体入口，本地路径
  锚点仍以资料所属仓库为准。若实际表达能力不足，说明具体缺口，不以拆散业务或
  虚构执行关系掩盖。未引入跨仓库全局 ID、新持久字段或自动推断流程。
- 影响：[主 Skill](../../.agents/skills/semantic-atlas/SKILL.md)、其业务边界／流程设计／
  文件编写参考、项目 Agent Guide、双 README、[产品契约](../product-contract.md)、
  [文件格式](../map-format.md)、[评估](../evaluation.md)与现有编图案例的阅读评分依据。
- 验证：Skill 结构、既有 3 文件 6 项检查及差异检查通过，独立内容审查通过。此前
  6 条独立流程试用的结论已收窄，不再作为项目全貌完成的证据。新版新上下文试用将
  六个接口入口组织为三个业务入口，4 文件／9 流程的校验、渲染与导航通过，未做
  浏览器阅读验证；同时暴露多入口、事件扇出与状态联系的同图表达缺口，详见
  [评估边界](../evaluation.md)。此次仅修改指导与验收资料，没有重建真实项目图、
  改变流程格式、安装或发布。
