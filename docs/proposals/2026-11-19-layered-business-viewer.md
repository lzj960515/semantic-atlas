# Semantic Atlas 业务流程阅读器

- 日期：2026-11-19。
- 状态：按用户确认的方向重写本地产品，等待实际阅读反馈；未发布。
- 目的：人和 AI 围绕业务流程协作。只有 AI 编辑资料，人通过只读画布逐层阅读和讨论。
- 现役契约：[产品契约](../product-contract.md)、[架构](../architecture.md)、[地图格式](../map-format.md)。

## 当前决定

所有图统一为业务流程图。总览同样需要动作、顺序、条件与结果，不能只列业务分类。
例如订单总览先交代顾客下单付款，再到仓库发货，顾客申请退款时进入售后；每一环节
可继续进入自己的子流程。

用户允许从需求重新设计产品，原理解业务和维护业务的两个 Skill 合并为一个。
阅读器采用 A 原型的紧凑卡片与轻量视觉，删除上一版依赖旧关系投影的分类入口。

| 位置 | 阅读行为 |
| --- | --- |
| 顶部 | 多项目选择与“查看其他流程”级联菜单 |
| 画布 | 当前流程、返回、平移、缩放 |
| 节点 | 起点、判断、结果有样式区别；子流程用叠层提示 |
| 点击 | 正文有备注时打开详情；无备注的正文保持原样 |
| 详情 | 默认关闭，只显示业务备注 |
| 返回 | 沿实际访问顺序恢复上一图与视野 |

节点上只保留子流程角标作为进入入口，详情不再放进入按钮。没有常驻目录、上下层预览、源码位置、AI 编排理由、统计与
图例。业务规则为什么成立可以写在备注；AI 为什么把图这样排不放到业务界面。

## 文件与进入路径

继续使用 v1 的 `nodes / relations / flows / concept / notes / anchors`，本轮不新增
持久化字段。AI 显式编写总览与子流程；步骤通过 `concept` 引用场景后，进入该场景
自有的流程。`part_of` 只描述业务归属，不能被推断成执行顺序。

未被其他流程引用其场景的根流程优先显示，随后沿步骤引用排列子流程。步骤对本流程
场景的引用不构成父层。所有流程都能从顶部按需选择；没有流程资料时显示空状态。

原有概念查询、校验、源码锚点和观察资料继续为 AI 提供证据。Web 只取得阅读所需的
业务内容，源码锚点留在文件和 CLI。没有从分类自动合成流程的兼容分支。

## 阅读器与统一 Skill

阅读器重新实现为 HTML 卡片与 SVG 正交连线，使用细边框、轻阴影、顶色条、小图标、
圆角转折和同色小箭头。根据可用画布比较横向与纵向布局的可读比例，选择更合适的
方向；默认适应不超过原始比例。长文字按实际高度重新布局，内容可以选择与复制。
静态 HTML 和本地 Web 使用同一实现。

产品只内置一个 [semantic-atlas Skill](../../.agents/skills/semantic-atlas/SKILL.md)，
在同一工作流理解业务、核实证据、编写和维护流程。[流程设计方法](../../.agents/skills/semantic-atlas/references/diagram-design.md)
指导 AI 判断每图边界、层次、完整分支、业务背景与修改范围。软件负责表达、校验与
阅读能力，图的业务组织由 AI 根据证据决定。

[订单示例](../../examples/订单管理/README.md)是虚构阅读样例，用来验证总览、
子流程、分支与导航。完整跨仓库业务总图需要另行调查和编写；本轮不声称已完成迁移。

## 验收

1. 打开即看到有连线和分支的业务总流程，能从入口走到结果。
2. 节点卡片、条件标签和箭头在实际窗口可清楚阅读。
3. 正文有备注时才打开默认关闭的详情，子流程由角标直达，多目标先选择。
4. 深入、返回、直接跳图与平移缩放保持一致。
5. Web 隐藏源码与编排理由；文件和 CLI 保留 AI 所需依据。
6. 统一 Skill 能从业务调查继续到文件维护，新安装只交付一个入口。

旧 A/B/C 原型只保留为本地实验依据，已被否定的目录、节点按钮和说明不再成为产品要求。

## 同步维护与 AI 定位

业务代码与图在同一分支同步修改、检查和合入。合并冲突依据最终代码重审流程，
不先留候选再等主干维护。旧格式兼容不作为产品约束，既有业务文件待新版后重写。

人用级联菜单浏览；AI 类比已有业务记忆，按已知编号或业务描述直接定位相关流程。
缺少上下文时才补看上下层，目录不是AI的必经入口。当前搜索仍是本地词面匹配，
通过业务资料定位代码锚点，没有把它宣传成语义向量检索。
